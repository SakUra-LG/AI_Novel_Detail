## 项目增强：武打“前期压制→中段转机→后期反杀”技术说明

本文档说明在现有 RAG 创作系统中，如何实现“前期一方劣势、后期反杀”的跌宕武打情节，包括提示词规范、代码改动点、运行与验证方法以及相关依赖变更。

### 1. 背景与目标
- 目标：解决以往直接碾压或过早反杀的问题，强制拉长“前期压制”的铺垫，并赋予合理的转机与克制的反杀结尾。
- 范畴：提示词系统增强（系统消息与模板函数）、RAG 检索策略配合、生成参数建议、运行与验证清单。

### 2. 架构概览（与原系统的关系）
- 保持原有流程：用户输入 → 语义检索（素材/专业）→ 提示词构建 → Qwen 生成。
- 新增/强化：
  - 在 `main.py` 的系统提示词加入“武打场景特殊要求”（比例/段落/次数/心理线/禁止项）。
  - 新增 `generate_fight_scene_with_reversal(prompt)` 模板函数，强制结构化输出并优先走该模板（当用户意图为武打/对决等）。
  - 优化模型加载为 safetensors（避免 `.bin` 安全限制），以保证初始化与检索模块稳定运行。

### 3. 代码改动点
#### 3.1 系统提示词（System Message）强化
文件：`main.py`
- 在 `system_message["content"]` 中新增/替换“武打场景特殊要求”，核心约束：
  - 篇幅比例：压制≈60%，转机≈20%，反杀≈20%。
  - 段落节奏：按【压制阶段】【绝境加深】【微小转机】【反杀爆发】推进。
  - 次数与细节：≥5 次有效压制、≥3 次无效反击；每次交锋要有技法细节、受力反馈与环境互动；体现累积性代价（体力/内息/伤势/武器/地形）。
  - 心理线：压迫→焦灼→冷静→决断，每次变化由具体外因触发。
  - 禁止：跳过压制直接反转、空话堆砌、结尾总结陈词（收束留白）。

示例（片段，实际以代码为准）：
```python
武打场景特殊要求：
- 结构比例：前期压制≈60%，转机≈20%，反杀≈20%
- 段落节奏：分为【压制阶段】【绝境加深】【微小转机】【反杀爆发】四段
- 压制阶段最低要求：
  1) ≥5 次对方有效命中/压制 + ≥3 次主角无效反击
  2) 每次交手包含招式/劲路/受力点/内力/呼吸/环境干扰等细节
  3) 呈现累积性消耗与外在压力（倒计时/禁制/地形）
- 绝境加深：再追加一次“几乎必败”的重压，禁止提前反转
- 转机限定：仅能来源于洞察破绽/环境/诱敌/弃子求变/以伤换势中的 1–2 种
- 反杀约束：对手轻敌或惯性出招时切入破绽，≤2 招半结束
- 心理线：压迫→焦灼→冷静→决断（由外因触发）
```

#### 3.2 反转模板函数
文件：`main.py`
- 新增/替换 `generate_fight_scene_with_reversal(prompt)`，通过“强命令式”模板约束篇幅与段落：
```python
def generate_fight_scene_with_reversal(prompt):
    reversal_template = """
    请按“武打四段”创作，严格遵循篇幅比例与最低次数要求：
    - 篇幅比例：压制≈60%，转机≈20%，反杀≈20%
    - 四段顺序：【压制阶段】【绝境加深】【微小转机】【反杀爆发】

    写作硬性要求：
    1) 压制阶段（≈60%）：
       - ≥5 次对手有效命中/压制 + ≥3 次主角无效反击（逐次加重）
       - 每次交锋必须出现技法细节（力路、角度、受力反馈、招式拆解、环境互动）
       - 呈现累积性代价（体力/内息/伤口/武器/地形限制），并有“倒计时/禁制/约束”的外在张力
    2) 绝境加深（≈10%）：再遭一次“几乎必败”的致命压制，禁止反转
    3) 微小转机（≈10%）：仅允许来源于洞察破绽/环境利用/诱敌深入/弃子求变/以伤换势中的 1–2 种
    4) 反杀爆发（≈20%）：对手轻敌或惯性出招时切入破绽，≤2 招半结束，过程克制紧凑

    心理与节奏：
    - 心态线：压迫→焦灼→冷静→决断；每次变化由具体外因触发
    - 禁止空话与总结陈词，不写结果之后的收束

    具体场景要求：{prompt}
    """
    return chat_once(reversal_template.format(prompt=prompt))
```
- 主函数中：若用户输入含“武打/战斗/对决/打斗/比武”等关键词，则优先调用该函数。

#### 3.3 模型加载方式
文件：`Search_content.py`、`Search_profession.py`、`Handle_Content.py`、`Handle_Profession.py`
- 统一使用：
```python
AutoModel.from_pretrained(model_path, use_safetensors=True)
```
- 若本地无 `model.safetensors`，请将 `pytorch_model.bin` 转换或下载官方 safetensors。

### 4. RAG 检索如何协同“前期压制”
- 内容检索（`Search_content.py`）：
  - 建议在素材库 `knowledgeBase/Content.txt` 中补充“持续压制、失败反击、环境不利、倒计时/禁制”等细节片段，使检索更偏向“铺垫”素材。
  - 可在检索结果融合时（系统提示词内）标注“参考内容偏向压制片段”，引导模型先写压制。
- 专业检索（`Search_profession.py`）：
  - 强化“技法拆解/内功运行/以伤换势/诱敌深入/地形利用”等专业条目，有助于生成更具体的压制过程与转机。

### 5. 生成参数建议
- `temperature`：0.85–0.95（略高，便于产生更丰富细节，但已用强约束减散逸）。
- `top_p`：0.8–0.9。
- `repetition_penalty`：1.1–1.2，降低复读。

### 6. 运行步骤（摘要）
1) 首次或素材更新：运行 `Handle_Content.py`、`Handle_Profession.py` 以更新向量与 JSON。
2) 若使用本地模型：确保 `bge_large_zh/model.safetensors` 存在（无则转换 `.bin` 或下载 safetensors）。
3) 运行主程序：`python main.py`，输入含“武打/对决/打斗/比武”等关键词的需求。

### 7. 验证清单（确保“压制足够长”）
- 篇幅比例是否满足：压制≈60%、转机≈20%、反杀≈20%。
- 是否出现≥5 次对手有效压制与 ≥3 次主角无效反击（且逐次加重）。
- 每次交锋是否有具体技法细节与环境互动；是否体现累积性代价。
- 是否设置外在压力（倒计时/禁制/地形）并影响抉择。
- 绝境是否另起一段并禁止提前反转；转机是否仅来自规定来源。
- 反杀是否克制（≤2 招半）并在对手轻敌或惯性出招时切入破绽。
- 心理线是否按压迫→焦灼→冷静→决断推进，且由外因触发。

### 8. 常见问题（FAQ）
Q1：前期仍然写不长？
- 提高“次数”要求（如压制≥6、无效反击≥4）。
- 在系统提示词末尾追加硬约束：若压制未达 60% 篇幅，自动补写压制片段后再进入后续段落。

Q2：细节不够具体？
- 在提示词中点名“每次交锋需包含：招式名/力路/受力点/呼吸/步法/场地反馈（墙面碎裂、尘土涌动、罡风轨迹）”。
- 扩充 `Content.txt` 中与“受力反馈/环境互动”的素材。

Q3：转机显得牵强？
- 严格限定来源于 1–2 个机制；并让“转机线索”在前文压制阶段出现过伏笔（例如对手习惯、地形结构、武器损伤）。

### 9. 依赖与安全说明
- 为规避 `torch.load` 安全限制（CVE-2025-32434），本项目建议：
  - 优先使用 `model.safetensors` 本地权重，并在代码中启用 `use_safetensors=True`。
  - 若必须使用 `.bin`，需升级 `torch` 至 ≥2.6（或改为 CPU 版高版本）。
