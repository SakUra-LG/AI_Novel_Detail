# 武打场景细节展开

## 功能目标

该功能把简短的战斗设定扩展为一段有完整胜负结果的武打场景，重点不是招式名堆砌，而是让动作、受力、环境、伤势、心理与战术选择形成连续因果。

核心入口是 `src/main.py` 中的 `generate_fight_scene_with_reversal(prompt)`。

## 实现方法

流程先用与神话功能相同的本地 RAG 模块检索：

- `retrieval_content.py`：寻找拳法、剑法、环境互动等描写素材。
- `retrieval_profession.py`：寻找节奏、动作和人物塑造等写作知识。

检索内容与用户设定一起进入固定的“武打四段”提示模板：

1. **氛围铺垫**：至少约 200 字，从视觉、听觉、触觉、嗅觉、空间位置、人物状态和冲突前因展开。
2. **压制阶段**：约占正文 60%。对手至少形成 5 次有效压制，主角至少有 3 次无效反击，并逐次累积体力、伤势、内息、武器或地形代价。
3. **绝境加深**：追加一次近乎必败的致命压力，此处不得提前翻盘。
4. **微小转机**：只从洞察破绽、利用环境、诱敌深入、弃子求变或以伤换势中选择 1～2 种。
5. **反杀爆发**：抓住对手轻敌或惯性出招造成的窗口，在最多“两招半”内完成胜负，不写到关键处突然停止。

模板还要求：所有主要人物有明确姓名；交锋通过动作自然衔接，不用“第一击、第二击”等机械计数；心理线按“压迫—焦灼—冷静—决断”变化；输出约 1500 字。

当前实现是单次结构化生成，随后执行通用 Markdown 清洗。与神话长篇流程不同，它没有逐段自动重写和独立的规则审计，因此交付前尤其需要人工检查。

## 如何运行

先按根目录 [README](../README.md) 安装依赖、下载 BGE 模型并设置 `DASHSCOPE_API_KEY`。

推荐使用统一入口：

```powershell
python run.py fight --prompt "雨夜，年轻剑客沈砚在废弃古寺对决拳师韩崇。沈砚起初被贴身拳法压制，最终利用钟绳和湿滑地面反杀。"
```

保存正文：

```powershell
python run.py fight `
  --prompt "女刀客苏照在竹林对决追兵首领陆骁，风雨限制听觉，转机来自竹枝回弹" `
  --output "outputs/竹林对决.txt"
```

使用仓库内置场景演示：

```powershell
Set-Location src
python demo.py
Set-Location ..
```

`demo.py` 会生成古寺中年轻剑客对拳法宗师的场景，并在当前目录写入带时间戳的 `demo_output_*.txt`。该类文件已被 Git 忽略。

也可运行 `python src/main.py`，输入含“武打、战斗、对决、打斗、比武”任一关键词的提示。若提示同时含神话关键词，旧交互入口会优先进入神话流程，因此推荐使用 `run.py fight`。

## 提示词建议

高质量输入至少应给出：

- 双方姓名、武器或拳种；
- 地点、天气、光线及可利用的环境物件；
- 冲突原因和胜负代价；
- 主角的初始劣势；
- 允许的转机方向；
- 暴力尺度和文风偏好。

示例：

```text
写一段约1500字的武打场景。巡检司女刀客苏照在暴雨码头拦截私盐首领陆骁。
陆骁用短桥贴身拳持续压制，苏照左肩有旧伤，身后货船即将离岸形成倒计时。
转机只能来自缆绳与湿滑甲板，不能突然出现援兵或隐藏神功。动作写实克制，必须写完胜负。
```

## 输出验收清单

人工通读时检查：

- 五个阶段是否齐全且顺序正确；
- 压制篇幅是否明显长于转机和反杀；
- 每次受击是否改变了后续动作，而非伤势写完就消失；
- 招式、距离、站位、惯用手和武器状态是否连续；
- 转机是否在前文有可观察线索；
- 主角是否付出代价，而非突然能力升级；
- 反杀是否明确完成；
- 是否残留“第一击/第二击”等计数写法、模型说明或总结陈词。

现有输出示例位于 `examples/fight/`。其中 `武打1.txt` 和 `武打2.txt` 是历史结果，不代表全部规则都已满足：例如旧稿中仍能看到计数式表达或反杀不完整的问题，适合用作回归时的反例与对照，不应直接作为最终质量标准。

## 调整模板

武打模板位于 `src/main.py` 的 `generate_fight_scene_with_reversal`。调整时应同时查看 `chat_once` 中的武打系统提示，因为当前实现会把四段模板作为用户提示，再由 `chat_once` 加上一层系统规则。

修改建议：

- 调整篇幅或暴力尺度时，两个位置保持一致；
- 不要把最低交锋次数改成要求模型显式编号；
- 新增转机类型时，明确它需要在压制阶段预埋什么线索；
- 修改后至少用古寺、竹林、船舱三种空间测试站位与环境互动。

## 常见问题

- **没有进入武打流程**：使用 `python run.py fight ...`，不要依赖关键词识别。
- **开场过短**：在输入中明确天气、光线、声音、气味、地形和冲突原因。
- **招式很多但没有因果**：要求每次命中改变伤势、武器、位置或心理中的至少一项。
- **突然翻盘**：把允许的环境物件和破绽写进提示，并明确禁止援兵、秘宝和临时升级。
- **模型重复编号**：提示中再次强调“自然叙述交锋，不使用序数词”，生成后人工删除残留计数式句法。
